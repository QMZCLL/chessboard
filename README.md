# 中国象棋学习助手 🚩

感兴趣的小伙伴请点击右上角`star`收藏

## 项目简介

“象棋学习助手”帮助象棋爱好者从任意局面开始学习：建立局面、确认轮到哪一方走、自己思考或在棋盘上试走，
然后查看**红黑双方每一着**的讲解——这步改变了什么、为什么值得考虑、其他选择有什么差别、对手会怎样应对——
并能在棋盘上逐步演示，把试走保存为分支，关闭后继续复盘。

建立局面的方式有四种：标准开局、手动摆棋、FEN 导入、棋谱导入。屏幕识别是其中一种可选的输入方式；
识别模型不可用时，其余学习流程照常使用。

## 🎯 核心功能

- **任意局面进入**：标准开局、摆棋（行棋方必须明确选择，与棋盘方向分开保存）、FEN、中文/ICCS/PGN 棋谱、本应用导出的学习数据。
- **完整校验**：FEN 格式、棋子数量与位置、将帅照面、非行棋方被将军；将死与困毙作为正常终局展示原因。
- **合法走子与具体说明**：蹩马腿、塞象眼、炮架数量、送将、将帅照面等非法走法给出原因并在棋盘上标出。
- **棋谱树**：主线与分支、设为主线、删除、笔记与收藏；屏幕识别无法补全的变化以“缺口”节点开始新的一段。
- **逐着讲解**：每一着都有讲解任务。先给出规则计算的事实（吃子、将军、应将、攻击、保护、线路与炮架变化），
  再用引擎多候选搜索补充候选比较和对手的主要应对；实际走法不在候选中时用 `searchmoves` 单独分析。
  讲解分为一句话结论、当前需求、具体依据、候选比较、主要应对、学习点，每条结论都关联证据，点击即可高亮或演示。
- **分析稳定性**：引擎每完成一个深度的完整一轮都记下首选与前几名，按最近 4 个深度判断结论稳不稳定：
  高稳定、中等稳定、排名仍在变化、分析不完整，并写明依据（首选是否刚换过或来回变化、前几名的次序、评分是否单向漂移、
  首选是否只是边界值）。它衡量的是这次搜索的结论是否还在变化，不是走法正确的概率，不换算成百分比。
  排名仍在变化时，讲解不称“引擎首选”、不按分差评价（损失很大的严重失误除外），两步对比与复习中的局面决策不比较先后，
  AI 讲解也不得说哪一着更好；快速分析仍在变化时，引擎空闲时补充一次深入分析（可在设置中关闭）。
- **AI 讲解（可选）**：把规则事实、引擎候选与证据质量整理成证据包交给语言模型（DeepSeek、OpenAI 或本机 Ollama），
  由模型组织成适合学习者的讲解；模型只能引用程序给出的结论编号，输出经过结构、引用与硬结论检查
  （新增的着法、胜率、未经确认的杀棋、分析不完整时的优劣评价都会被拒绝）才会显示，点击段落同样可以高亮和演示。
  评分与其他数字、排名（首选）、评价等级、优劣方向、杀棋与胜负这类硬结论由程序给出：输出检查用关键词与引用
  限制模型文字中出现这些表达，程序则在每段（含一句话结论与学习要点）下方显示所引用结论的原文；
  模型选择要讲的结论，并解释作用、理由与需要注意的地方。这些检查限制的是硬结论的表达，
  并不是对自由文字语义的完整验证。
  模型服务不可用或输出不合格时，模板讲解照常可用。关闭功能、清除密钥或更换模型后，尚未发出的请求不再发送。
  证据、模型或讲解设置改变后，旧的 AI 讲解标为过期；相同条件下直接复用，不重复调用。
  设为“查看某一着时自动生成”时，在一着上停留约半秒才发起请求，快速翻阅经过的着法不调用模型；
  离开这一着时，还没有发出的请求不再发送，已经发出的照常完成并归入原来的着法。
  棋谱上方的“批量 AI 讲解”可以为收藏的着法、从当前着法到这条线的最后或整条主线生成讲解：
  开始前说明要生成几着、预计调用几次、今天还剩几次；生成时逐着进行，可以暂停、继续、停止，失败的着法可以重试，
  今天的调用次数用完时自动停止。
- **教练追问（可选，需要 AI 讲解）**：试走对比的同一次搜索完成后，可以就这组对比提出三类问题：
  我的这一步起了什么作用、两步的差别在哪里、走这一步之后对方的回应需要怎样应对。
  证据只取这组对比已有的规则事实与搜索结果，提问不发起新的搜索；回答与 AI 讲解经过相同的引用与硬结论检查，
  每段下方显示所引用的程序结论原文，演示的变化由程序按问题选择，最后留一个让学习者自己在棋盘上验证的问题。
  回答按比较起点、两步着法与问题类型保存：离开后再回到这组对比仍然显示，对比依据或讲解设置改变后标为过期，可以重新回答。
  调用次数、并发与重试和 AI 讲解共用。第一版只提供这三类结构化问题，不支持自由输入。
- **两种学习节奏**：自动讲解；先想后讲（先在棋盘上走出自己的选择，再与实际着法对照）。
- **复习卡片**：先想后讲揭示后，或在任意一着的讲解下方“加入复习”；也可以把一盘棋收藏的着法一起加入。
  卡片保存落子前的局面与此前的着法、当时的第一次选择与看过的提示原文、棋谱中的这一着、程序讲解的要点与依据
  （连同分析条件与讲解规则版本），以及自己的理解或疑问（加入时从这一着的笔记带入）。
  复习时先只显示局面，在棋盘上重新选择（或直接看答案）后，才显示这次的结果、原来的思考与讲解；
  状态只有待复习、需要再练、已理解三种。练习目标分两种：复现棋谱只看是否与棋谱一致；局面决策先用多候选搜索找出引擎参考，
  再把这次的选择、棋谱着法与引擎参考放在同一次搜索中比较，结论只有“与棋谱一致”“与参考评分接近”“留下了值得注意的问题”
  “分析尚不充分”四种（棋谱着法明显不如引擎参考时改用引擎参考对照）。落子前可以选择意图（出子、防守、吃子、将军、改善位置），
  揭示后与这一步实际的规则事实对照（受到的威胁包括被吃后不能吃回、以及能吃回但攻击者价值更低两种）。
  “与棋谱一致”只陈述匹配的事实，这次比较是否支持这个选择另外记录，与其他选择用同一套判断：走了棋谱着法时与引擎参考比较，
  同样的分差得到同样的评价，评分无法比较或缺少结果时不评价；早期版本记录的“与棋谱一致”没有质量依据，按无法评价处理。
  局面决策只在比较不支持这个选择时建议再练，与棋谱一致不自动视为已理解。卡片是独立的快照，原会话之后被修改或删除仍可复习，
  只是不能再打开原局面。
- **到期复习与每日练习**：状态之外记录下一次复习的时间。标记状态时按最近一次复习安排间隔：标为需要再练，
  或直接看答案、没有独立选对后标为已理解，都在第一档（默认明天）再看；局面决策无法评价时档位不变，
  比较还没有结果时先这样安排、结果出来后按结果重新安排；同一次复习重复标记不会重复升档；独立选对后标为已理解则升一档
  （默认 1、3、7、14、30 天，可在设置中调整；这是可以调整的初始设计，不宣称对所有人都最合适）。
  复习入口与“今天”分组按本机日期显示今天到期的卡片；可以开始今天的练习（5 张、10 张或全部）或只练需要再练的卡片。
  复习时可以看分级提示（与先想后讲相同，只依据局面，不透露棋谱着法），也可以选择这一步的把握（基本靠猜、有些把握、很有把握）；
  看了提示之后选对记为“看了提示后选对”，不算独立选对，标为已理解时不升档。揭示后写明看了几级提示、把握与用时（用时只记录，不评分）。
- **学习事件**：每次作答（复习、练习批次与先想后讲）记一条学习事件：局面、练习目标、结果（独立选对、看了提示后选对、没有选对、
  直接看答案、比较中、无法评价）、这一着的规则主题、当时确认的问题、提示级数、意图、把握、用时与比较搜索的稳定性，
  是能力画像的依据。复习的事件在写入作答的同一个写事务中写入，局面决策的比较结果晚到时更新同一条；卡片只保留最近 20 次作答，
  事件保留完整的历史。第一次启动时从已有的作答与练习记录补上事件；学习档案带上事件（早期的档案导入时同样补上）。
- **从自己的棋局生成练习**：整局报告中“从这盘棋生成练习”，按自己一方在主线上的着法出三种题，只用已经完成的讲解与规则事实：
  找威胁（落子前有没有保护、会被吃掉的棋子或正被将军，在棋盘上点出这些格子后提交，按规则事实判断；这一步评价不好或先想后讲中
  没有选对时才出）、二选一与找更好的着法（当时的着法与引擎首选在同一次搜索中、搜索高稳定、评价为“明显不如首选”或“严重失误”；
  二选一给出这两步，找更好的着法在局面中自己选择并按局面决策比较）。不满足门槛的失误不出唯一答案的题目并写明原因；
  缺口之后来自不确定识别的局面不出题；同一局面同一题型不重复加入。复习库标出题型，揭示后的结果、标签与讲解按题型说明，
  学习事件记下题型（找威胁算“受攻击棋子的处理”）。
- **复盘收件箱**：首页“导入棋局”一次导入多盘自己下的棋（粘贴或多选文件，一个文件里有多盘时按标签分开）。导入前预览每盘的着数、
  解析停在哪一步，并认出与已有的棋局或同一批中重复的（按起始局面与主线着法，记谱方式不同也认得出）；按设置中的“我的名字”
  与棋谱中的红方、黑方比对，判断哪一方是自己并写明依据，比对不上时在预览中选择。导入后每一着都在引擎空闲时排队详细讲解，
  不挡住正在查看的棋局，退出后下次启动继续；首页写明每盘的分析进度与关键局面数。出题不自动进行（生成的题目当天到期）：
  “为分析完的棋局出题”只为分析完、还没有出过题的棋局出题，并写明新增几道。第一版只支持文字棋谱，XQF 等二进制格式以后再做。
- **学习画像**：首页按学习事件回答三个问题，全部由程序统计、写明次数与依据，不显示百分比或分数（没有经过校准）：
  最近反复错在哪里（一个主题最近 30 天作答 4 次以上、一半以上没有独立选对时列出，附可以打开的例子）；
  今天最值得练什么（最需要练、又有两张以上卡片的主题，可以直接开始这一组）；掌握了还是记住了答案
  （区分在不同局面中独立选对、隔天以后再做时选对与同一局面当天重复答对）。另按子力粗分开局、中局、残局说明最近的作答。
  作答少于 5 次时只说明作答还不多，不下结论；画像没有推荐时，仍按自己确认的问题给出专题推荐。
- **今日学习与专注练习**：顶栏的“今日学习”（还没有打开学习局面时也显示）分三块：继续上次练习（练习目标、已作答与剩余题数）、
  今天到期、继续复盘最近的棋谱（回到上次看到的位置），下面是按自己确认的问题给出的专题推荐；主要操作随状态决定。
  开始一组练习后进入以棋盘为中心的专注练习工作区：顶部始终显示练习目标与进度，每个阶段突出一个主要操作，操作区固定在可见区域底部；
  揭示后的反馈分为“你的选择”“比较结论”“具体原因”“下一次检查什么”，比较中、无法评价、比较支持、比较不支持统一文字与颜色；
  “跳过”（没有作答就离开）与“直接看答案”（一次作答）分开记录；本组卡片列表写明每一题的进展。
  一组练习由后台保存：卡片顺序在开始时固定，当前题目、跳过的题目与练习目标随练习写回，可以随时保存退出，
  重新启动后从原处继续（已经作答的题目恢复到揭示之后）；练习中删除的卡片说明已跳过。作答带上所属的练习与请求编号，
  同一次作答的请求重复到达只记一次；比较结果晚到时写回原来那次作答，不切换当前题目。
  结束后的小结只统计属于这组练习的作答，每张卡片按这组中的第一次作答计算（独立选对、没有选对、直接看答案、比较还没有完成、
  无法评价、跳过与已删除分别说明），连同之后的安排都来自实际记录，比较结果晚到时随之更新。
- **整局报告**：棋谱栏上的“本局报告”从主线中选出最多五处值得复盘的局面，写明入选的依据（实际着法明显不如首选、
  先想后讲中自己的选择与棋谱不同或不如首选、用了较多提示、收藏、吃子与将军），可以在棋盘上查看或加入复习；
  另外列出值得保留的判断（先想后讲中选对或与首选接近）与需要重新观察的地方（只说明“这条关系值得重新检查”）。
  筛选与统计都由程序完成，文字取自已经生成的讲解；评价只比较每一着自己的候选，不同局面、不同条件的评分不直接相减。
  先想后讲中不能打开报告，避免透露尚未揭示的着法。
- **专题训练**：复习卡片附上程序根据这一着的规则事实建议的主题（应将与将帅安全、受攻击棋子的处理、保护关系变化、
  炮架与线路变化、吃子后的回吃关系）及依据；用户可以标记“我当时的问题”（没有检查对方的直接威胁、没有注意保护关系等）。
  复习列表可以按主题或问题练一组；同一个问题标记到两张以上卡片时推荐练习，并写明是哪些记录。
- **学习档案**：导出全部学习会话（含讲解）与复习卡片（历次复习、意图对照、比较结果、理解与安排），换设备时导入恢复。
  导入前先预览新增、保留与合并的内容；会话保留原来的编号，本机已有时保留本机的版本；同一张卡片的历次复习按时间合在一起，
  同一次复习取比较进行得更完整的一份，其他内容取较新的一份；导出时还在进行的比较在导入后重新排队，之后又导入了这次复习的完成结果时，排队的比较迟到的结果不再覆盖它；原会话已删除的卡片照样导入。预览与导入前检查档案是否成立（棋谱树的父子关系与可达性、
  节点编号、每一着与局面是否一致、卡片的局面与着法、数量与大小的上限），有不成立的内容时列出前几处、不导入任何内容；
  导入在一个数据库事务中完成，中途失败不会留下导入了一半的数据。每天第一次启动时自动备份一份（保留份数可调整），也可以立即备份。
- **引擎服务**：独立线程管理 Pikafish，完成 UCI 握手后只设置引擎支持的选项；评分区分普通分、将杀分与上下界；
  支持取消、优先处理正在查看的节点、超时重启、进程退出检测；不支持 MultiPV 的引擎按一个候选判断搜索是否完整；
  启动失败时附上引擎最近的错误输出；结果按完整分析条件缓存，引擎身份包含程序与网络文件内容的校验值
  （原位替换、名称与大小相同的文件不复用旧结果）。退出时依次停止屏幕连接、引擎（握手中也立即停止）、AI 讲解请求
  （排队的不再发送，已发出的最多等几秒）与讲解线程。
- **屏幕连接（可选）**：框选并校准棋盘区域，确认起始局面与行棋方后持续记录；连续多帧一致且能用一到两步合法走法解释时才记入棋谱，
  否则请用户确认或校正。用户在阅读历史节点时，新着法不会把视图切走。
- **本地保存**：学习会话、分支、标注、分析与讲解保存在本地数据库，可导出/导入单个会话的完整学习数据（导入前同样检查棋谱树是否成立），
  或导出/导入包含全部会话与复习卡片的学习档案。
- **可定位的故障信息**：状态栏分别显示引擎、识别资源、屏幕连接与讲解进度，可复制诊断信息、打开日志目录。

## 🏗 技术架构


## 🛠 开发

需要 Rust 1.88 及以上、Node.js 与 pnpm，以及各平台 Tauri 依赖。

```bash
pnpm install
pnpm tauri dev                     # 桌面应用
cargo test --manifest-path server/Cargo.toml -p xq-core -p xq-app   # 规则、讲解、引擎服务与流程测试
```

前后端之间的全部数据结构都由 Rust 生成 TypeScript 类型（ts-rs，见 `.cargo/config.toml`），界面不手写协议类型：
运行上面的 `cargo test` 时写到 `src/api/generated`，生成的文件随代码提交，CI 检查它们是否最新；
新增生成的类型时在 `src/api/generated/index.ts` 加一行（单元测试会检查有没有遗漏）。

界面状态在 `src/state` 中按职责分开：共享状态（`core.ts`）、会话视图的单调合并（`viewSync.ts`、`studyView.ts`）、
AI 讲解、先想后讲、棋盘显示、节点与讲解、演示、会话的打开与导入，`workbench.ts` 负责启动与订阅后台事件并统一导出；
复习与练习在 `review.ts`，按题型的规则在 `cardKind.ts`，复盘收件箱在 `inbox.ts`。

流程测试会运行仓库自带的 Pikafish，缺少引擎时测试失败而不是跳过；确实无法运行时，
可设置 `XQ_SKIP_ENGINE_TESTS=1` 明确跳过。引擎服务的异常情况（候选排名变化、部分更新、崩溃、设置变更）
由可编排的模拟引擎 `xq-mock-uci` 稳定复现，不依赖真实引擎。

数据升级、崩溃与后台任务的处理方式见 [docs/data-guarantees.md](./docs/data-guarantees.md)，对应三组测试：
旧版本实际写出的数据目录（`server/crates/xq-app/tests/history/`，生成后不再修改）的迁移与导入（`history.rs`），
在写入的关键位置终止进程后检查数据（`crash.rs`，故障注入点只在测试构建中启用），以及后台任务的生命周期（`lifecycle.rs`）。

在浏览器中调试界面（使用真实引擎，屏幕识别为模拟输入）：

```bash
pnpm bridge --data /tmp/xqlink-dev      # 开发桥，端口 1422
pnpm dev                                # 打开 http://localhost:1420
```

识别模型与 ONNX Runtime 运行库不在仓库中，放置方法见 [libs/README.md](./libs/README.md)。
缺少它们时应用仍可构建和运行，只是屏幕识别不可用。

AI 讲解默认关闭，在“设置 → AI 讲解”中选择模型服务、填写模型名称与密钥后开启。开启后，所查看这一着的局面、
着法历史与分析结果会发送到所选服务（Ollama 在本机处理）。密钥只保存在配置目录下的 `credentials.json`
（Unix 上权限为 0600），配置文件只记录引用；也可以手动把 `coach.credential_ref` 设为 `env:变量名` 从环境变量读取。
访问云端模型服务时按系统代理设置（`HTTPS_PROXY` 等环境变量）连接；本机地址（`127.0.0.1`、`localhost`，如 Ollama）不经过代理。
AI 讲解的流程测试使用本机模拟的模型服务，不需要网络或密钥。前端的评分显示、状态合并与 AI 讲解显示方式有单元测试：`pnpm test:unit`。

界面的操作流程由浏览器端到端场景检查（无头 Chromium + 开发桥 + 自带 Pikafish，使用临时数据目录与空闲端口）：

```bash
pnpm exec playwright-core install chromium   # 首次运行前
pnpm test:e2e                                # 全部场景；也可指定，如 pnpm test:e2e s7 s10
```

场景列表、运行方式与编写说明见 [tests/e2e/README.md](./tests/e2e/README.md)。

### 打包

发布的版本在 GitHub 的 [Releases](https://github.com/QMZCLL/chessboard/releases) 页面下载安装包。

GitHub Actions 的“打包”工作流生成 Windows 安装包（MSI）与 Linux 安装包（deb）：推送 `v` 开头的标签时运行，
工作流在默认分支上时也可以在 Actions 页面选择“打包 → Run workflow”手动运行；完成后在这次运行页面底部的 Artifacts 中下载。
也可以在本机打包：

```bash
pnpm build:cpu                                            # Windows（需在 Windows 上运行）：server/target/release/bundle/msi/
pnpm tauri build --config server/tauri.linux.conf.json    # Linux：server/target/release/bundle/deb/
```

安装包带有 Pikafish 2026-09-06 引擎（运行时按 CPU 选择指令集的通用构建）及其许可文件，
不含屏幕识别所需的模型与 ONNX Runtime（见 [libs/README.md](./libs/README.md)），
也没有代码签名：Windows 首次运行时如出现 SmartScreen 提示，选择“更多信息 → 仍要运行”。

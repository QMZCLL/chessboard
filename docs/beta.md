# Beta 1：可恢复、可迁移、可诊断的学习闭环

这一版不增加新的题型或功能，目标是证明已有的完整学习路径在真实的桌面使用中可靠：

建立或导入棋局 → 摆棋与分析 → 讲解 → 出题或重新出题 → 练习与复习 → 关闭再打开 → 导出、恢复或换到新版本。

验收标准：在干净的 Windows 环境中完成这条路径，途中即使强制关闭、重新启动、网络或引擎出错、重试，学习数据都不丢失、
不重复计分，不出现一直“进行中”的后台状态，并且能导出足够的信息定位故障。

## 保证与恢复

数据升级、写入的原子性与后台任务的处理见 [data-guarantees.md](./data-guarantees.md)。要点：

- 旧版本的数据在启动时迁移一次，迁移前先备份；中途终止时保持原样，下次启动重新迁移；来自更新版本的数据拒绝打开。
- 一次写入涉及的几项记录在同一个写事务中保存，进程在任何时刻终止都只会留下完整的旧状态。
- 每个后台任务都会结束；退出时没有完成的任务在下次启动时写明“上次没有完成”，可以重新发起。

## 诊断包

设置 → 诊断 → “导出诊断包”，得到一个 zip 文件，内容包括：

- 清单、系统概况、设置；
- 数据版本与迁移记录、隔离区概况；
- 后台任务的登记、最近的日志。

日志每行是一条 JSON；每个任务结束时写一行，带任务编号与操作编号。导出时自动清除：

- 密钥（包括本机保存的密钥原文）、Authorization 头、接口地址中的用户名密码与查询参数；
- 本机用户名与完整路径；
- 默认还清除局面、着法、会话名称与“我的名字”。只有勾选“诊断包中包含棋谱内容”时，才附上学习档案。

## 安装、升级与卸载

- 学习数据保存在用户目录中，不在安装目录：
  - Windows 为 `%APPDATA%\top.itmeng.xqlink`；
  - Linux 为 `~/.local/share/top.itmeng.xqlink`（数据）与 `~/.config/top.itmeng.xqlink`（设置）；
  - 日志在 Windows 的 `%LOCALAPPDATA%\top.itmeng.xqlink\logs`、Linux 的 `~/.local/share/top.itmeng.xqlink/logs`。
- 卸载只删除程序，不删除学习数据；重新安装后数据仍在。需要彻底删除时，手动删除上面的目录。
- 原地升级：直接安装新的安装包即可，旧版本被替换，学习数据在第一次启动时迁移，迁移前的数据库备份在数据目录的 `backups/` 中。
- `xqlink --smoke <报告文件> [--data <目录>]`：不打开窗口，检查服务能启动、引擎能就绪、数据库能打开并完成迁移、
  随安装包发布的引擎与许可清单都在，结果写成 JSON 报告。

## 发布门槛

| 门槛 | 检查 |
|---|---|
| 历史数据都能迁移，迁移失败不改写原文件，导出再导入内容相同 | CI：`tests/history.rs` |
| 进程在写入中途终止只会留下完整的旧状态或新状态 | CI：`tests/crash.rs`；浏览器场景 s29 |
| 重试不产生重复的讲解、题目、作答或学习事件 | CI：`tests/crash.rs`、浏览器场景 s29、s31 |
| 所有任务最终结束，删除或取消后到达的结果不写入，退出后没有遗留的引擎进程 | CI：`tests/lifecycle.rs`；浏览器场景 s31 |
| 外部依赖出错时等待会结束、说明原因、可以重试 | 浏览器场景 s30 |
| 完整学习闭环经过强制结束、重启与换数据目录后内容不变 | 浏览器场景 s28 |
| 诊断包能定位问题且不泄漏密钥与本机路径 | CI：`tests/diagnostics.rs`；浏览器场景 s30 |
| 浏览器场景连续 30 轮、竞态场景连续 100 轮全部通过，没有 panic 与遗留进程 | 手动触发的“发布前检查”工作流 |
| 干净环境安装（带空格与中文的路径）、从 v0.3.0 原地升级并迁移、卸载后数据保留、版本一致 | “打包”工作流（Windows MSI 与 Linux deb） |

发布步骤：

1. 分支上的 CI 全部通过；
2. 在这个分支上手动运行“发布前检查”，全部通过；
3. 确定版本号（安装包要求纯数字，如 0.4.0），更新 `package.json`、`server/tauri.conf.json` 与各 crate 的版本，推送 `v` 开头的标签；
4. “打包”工作流打出安装包并完成安装、升级与卸载检查后，发布安装包。

## 已知限制

- 安装包没有代码签名，Windows 会提示来源未知。
- 已经发给模型服务的请求不能中途取消：退出时最多等 3 秒，之后进程结束，这次 AI 讲解在下次启动时记为中断。
- 安装与升级检查只在 Windows 与 Linux 上进行，没有 macOS 安装包。
- 打包流程中的安装包不含屏幕识别所需的 ONNX Runtime 与模型（不在仓库中），屏幕识别在这些安装包中不可用。
- 升级检查从 v0.3.0 开始；更早的 0.1.x 版本没有学习数据，只迁移设置。
- 打包设置允许覆盖安装同一版本或较低版本（`allowDowngrades`），降级之后，较新版本写过的数据会被拒绝打开（不会被改写）。
- 诊断包不压缩；日志最多附上 2 MB。
- 30 轮与 100 轮的重复运行只在手动触发时进行，平时的 CI 每个场景运行一次。

这一版不包括：新的题型、更换引擎、新的模型服务、重写界面状态、云同步与账号、多设备。

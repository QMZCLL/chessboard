# 数据与后台任务的保证

本文说明学习数据在升级、崩溃与后台任务中的处理方式，以及对应的测试。

## 数据库的版本与迁移

学习数据保存在数据目录的 `xqlink.redb` 中，meta 表记下数据版本。

- 版本 1：0.3.0 的格式（0.4 开发期间加了收件箱表与几个可以缺省的字段，仍记为版本 1）。
- 版本 2（当前）：每条记录都按当前格式写回并检查过。

打开数据库时：

- 新的数据库：建立全部的表，记为当前版本。
- 来自较早的版本：
  - 先把数据库文件复制到 `backups/xqlink-schema<原版本>-<时间>.redb`，再在**一个写事务**中迁移；
  - 迁移中出错或进程终止时，数据库保持迁移前的内容，下次启动重新迁移；
  - 无法读取或不成立的记录原样移到隔离表（写明原来的表、键与原因），不丢弃，也不让启动失败；
  - 讲解、AI 讲解与追问中，所属着法已经不存在的记录删除；原会话删除后保留的复习卡片照常保留；
  - 每次迁移记在 meta 表的 `migrations` 中，启动后在界面上说明升级了数据、备份在哪里、隔离了几条记录。
- 来自较新的版本，或记下的版本无法识别：拒绝打开，不改动文件。

学习档案、单个会话的导出文件与配置文件各自带有版本：来自较新版本的拒绝导入；0.1.x 的配置文件迁移到新的位置，原文件保持原样。

**测试**：`server/crates/xq-app/tests/history.rs` 用旧版本实际写出的数据目录（`tests/history/`，见其中的说明）检查：

- 迁移只做一次，内容与旧版本自己读出的相同；
- 迁移前的副本与原数据库内容相同；
- 迁移后导出再导入、旧版本导出的档案与单个会话、旧版本的自动备份，导入后内容都相同；
- 中断状态的数据（AI 讲解与追问生成中、讲解进行中、局面比较等待引擎）启动后都有结果，不会一直显示进行中；
- 较新的版本被拒绝；
- 无法使用的记录进入隔离区，孤立的记录被删除。

## 写入的原子性

下面每一项都在一个写事务中完成，进程在中途终止时只会留下完整的旧状态（之后重新操作即得到完整的新状态）：

- 删除着法：会话与这些着法上的讲解、AI 讲解（含缓存）与追问；
- 删除会话：会话、它的讲解、AI 讲解、追问与收件箱记录；
- 先想后讲：练习记录与这次练习的学习事件；
- 复习作答：作答记录与学习事件；局面比较的结果与这次作答的学习事件；
- 出题与重新出题：一批题目；
- 导入学习档案、导入单个会话、收件箱导入。

属于某一着的记录（讲解、AI 讲解、缓存与追问）写入时，在同一个写事务中确认这一着仍在：删除着法之后才到达的结果不会留下不属于任何着法的记录。

文件（导出、自动备份、设置）先写到同一目录的临时文件（文件名后加 `.tmp`），刷到磁盘后再改名替换；Unix 上改名后把目录也刷到磁盘。写到一半终止时原来的文件不变，可能留下一个 `.tmp` 文件。

**测试**：`server/crates/xq-app/tests/crash.rs` 让子进程在注入点（`src/failpoints.rs`，只在测试构建中启用）直接终止，再检查数据：

- 删除着法：保存会话之后、提交之前；
- 先想后讲：同上；
- 出题：一批写到一半、提交之前；
- 复习作答、收件箱导入、导入学习档案：提交之前；
- 写文件：写到一半、改名之前（导出与保存设置）；
- 迁移：备份之后、迁移完会话之后、提交之前。

## 后台任务

每个后台任务登记在任务登记中（`src/jobs.rs`），开发桥与桌面程序的 `job_history` 命令可以读取：

- `job_id` 是一次实际执行，`operation_id` 是用户的一次操作，重试保留同一个操作编号，`attempt` 加一；
- `key` 是任务针对的对象；同一对象开始新的任务时，之前还没有结束的任务记为“被取代”；
- 状态依次为排队、进行中，最后是成功、失败、取消、被取代或中断之一；结束后不再改变；
- 登记只在内存中，保留最近结束的 500 条。

各类任务的处理：

- **讲解**（含收件箱的分析）：
  - 切换会话时继续，结果写入原来的会话；
  - 删除着法或会话时取消，晚到的结果不写入；
  - 同一着开始新的请求时取代旧的；引擎设置在排队期间改变时按新设置重新排队；
  - 候选分析完成而实际着法的分析失败时，写入并标为部分完成；
  - 退出时讲解线程处理完已经得到的结果（最多 5 秒），其余记为中断；
  - 下次启动时，打开会话即重新排队；收件箱中的棋局在启动时排队。
- **局面分析**：
  - 界面的请求编号就是操作编号；取消即结束；
  - 引擎设置改变时按新设置重新分析，算作同一操作的下一次执行；
  - 结果只推送给界面，不写入学习数据；重新启动后不恢复，由界面重新请求。
- **试走对比**：同一局面的新对比取代旧的；结果只推送给界面；重新启动后不恢复。
- **局面决策的比较**：
  - 同一次作答的比较是同一个操作；
  - 结果与学习事件在同一个写事务中写入，只换成更进一步的结果（迟到的失败不覆盖已经完成的结果）；
  - 退出时记为中断；下次启动时标为“上次比较在应用退出前没有完成”，可以重新作答。
- **AI 讲解与追问**：
  - 离开这一着时，排队的请求不再发送，已经发出的继续，结果写给这一着；
  - 取消后已经发出的请求返回时不改动讲解状态（结果可以存入缓存）；删除着法或会话时取消；
  - 模型服务设置改变时，之前的请求被取代，按新设置重新安排；
  - 网络错误与输出不合格的重试都在同一个任务内（一着最多调用 4 次）；
  - **已经发出的请求不能中途取消**：退出时最多等 3 秒，之后进程结束，任务记为中断；
  - 下次启动时标为中断，可以重新生成或重新提问。
- **出题、导入、导出、备份与云库查询**：
  - 在命令中同步完成，返回前不会被取消；
  - 出题时重复点击结果不变，重新出题只替换没有作答过、内容又变了的题目；
  - 云库的结果存为缓存，退出时进行中的查询记为中断。

**测试**：`server/crates/xq-app/tests/lifecycle.rs` 检查：

- 全部任务最终都进入结束状态；
- 删除着法、取消 AI 讲解与取消分析之后到达的结果不写入，也不改变任务记录；
- 只有成功的任务写入数据；
- 退出后没有进行中的任务，也没有留下引擎进程；
- 下次启动时记下上次中断的任务，界面不会一直显示生成中。
